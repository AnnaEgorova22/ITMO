# ML Service Platform

## Описание проекта

Проект представляет собой сервис для выполнения ML-предсказаний с поддержкой:

- REST API (FastAPI)
- Асинхронной обработки задач (RabbitMQ + workers)
- Пользовательского веб-интерфейса (Jinja2)
- Управления балансом пользователей
- Истории операций и ML-задач

Система реализует сквозной пользовательский сценарий:
регистрация → пополнение баланса → выполнение ML-запроса → получение результата.

---

## Архитектура системы

В состав системы входят:

- **Backend (FastAPI)** — API и веб-интерфейс
- **PostgreSQL** — хранение пользователей, баланса, задач и транзакций
- **RabbitMQ** — очередь задач
- **Worker-сервисы** — обработка ML-задач
- **Nginx (web-proxy)** — точка входа

### Поток выполнения ML-задачи

1. Пользователь отправляет запрос через UI или API
2. Backend создаёт задачу
3. Задача отправляется в очередь RabbitMQ
4. Worker получает задачу
5. Выполняется ML-предсказание
6. Результат сохраняется в БД
7. Пользователь получает результат через API

## Основные API эндпоинты

### Аутентификация

- `POST /auth/register` — регистрация пользователя  
- `POST /auth/login` — авторизация  

---

### Баланс

- `GET /balance/{user_id}` — получить баланс  
- `POST /balance/{user_id}/top-up` — пополнение  

---

### ML-запросы

#### Синхронный режим

- `POST /predict` — выполнение предсказания  

#### Асинхронный режим (RabbitMQ)

- `POST /predict-async` — постановка задачи в очередь  
- `GET /tasks/{task_id}` — получение результата  

---

### История

- `GET /history/{user_id}/tasks` — история ML-задач  
- `GET /history/{user_id}/transactions` — история операций

- age

## Асинхронная обработка (RabbitMQ)

RabbitMQ используется для:

- постановки задач в очередь
- распределения нагрузки между worker-сервисами

Особенности реализации:

- несколько worker-сервисов
- обработка сообщений с подтверждением (ack)
- повторные попытки подключения
- обработка ошибок
- возврат средств пользователю при сбое

---

## Логика баланса

- списание средств при успешном ML-запросе
- проверка достаточности средств
- запрет выполнения при недостаточном балансе
- возврат средств при ошибке обработки задачи
